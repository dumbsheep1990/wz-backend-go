## 核心模型详情

### 基础模型 (common)

```go
// BaseModel 基础模型接口
type BaseModel interface {
    GetID() int64
    IsDeleted() bool
}

// BaseIDModel 基础ID模型
type BaseIDModel struct {
    ID int64 `json:"id" db:"id" gorm:"primaryKey;autoIncrement"`
}

// BaseTimeModel 基础时间模型
type BaseTimeModel struct {
    CreatedAt time.Time  `json:"createdAt" db:"created_at" gorm:"autoCreateTime"`
    UpdatedAt time.Time  `json:"updatedAt" db:"updated_at" gorm:"autoUpdateTime"`
    DeletedAt *time.Time `json:"deletedAt,omitempty" db:"deleted_at" gorm:"index"`
}

// Response 通用响应结构
type Response struct {
    Code    int         `json:"code"`
    Message string      `json:"message"`
    Data    interface{} `json:"data,omitempty"`
}
```

## 模型设计特点

### 1. 统一的基础模型

所有业务模型都继承自common包中的基础模型，确保了以下共同特性：

- 唯一标识（ID）
- 创建和更新时间戳
- 软删除支持
- 标准JSON序列化

### 2. 完善的标签系统

每个模型都使用了三种标签类型，便于不同场景的数据转换：

- `json`：用于API响应和请求
- `db`：用于sqlx等原生SQL映射
- `gorm`：用于ORM映射

示例：

```go
type User struct {
    BaseIDModel
    BaseTimeModel
    Username  string     `json:"username" db:"username" gorm:"size:64;uniqueIndex"`
    Email     string     `json:"email" db:"email" gorm:"size:128;uniqueIndex"`
    TenantID  int64      `json:"tenantId" db:"tenant_id" gorm:"index"`
}
```

### 3. 多租户支持

所有业务模型都包含TenantID字段，支持多租户隔离：

- 统一的租户字段命名
- 自动的索引创建
- 查询时的租户过滤

### 4. 模型组合模式

通过组合而非继承方式构建复杂模型：

- 基础字段通过嵌入BaseIDModel和BaseTimeModel获得
- 跨领域复用通过组合实现
- 服务特定扩展通过组合基础模型实现
