# 用户积分服务DDD架构设计

## 1. 概述

用户积分服务是WZ系统中的核心服务之一，负责管理用户积分的增加、减少、统计和规则配置。本文档描述了使用领域驱动设计(DDD)对该服务进行的架构设计。

## 3. 领域模型

### 3.1 核心概念

- **积分记录(UserPoints)**: 表示用户单次积分变动，可以是增加或减少
- **积分规则(PointsRules)**: 定义各种行为的积分奖励标准和积分使用规则
- **积分类型(PointsType)**: 区分积分增加和减少
- **积分来源(Source)**: 标识积分的来源，如签到、购买、活动等

### 3.2 聚合根

- **UserPoints**: 积分记录聚合根
- **PointsRules**: 积分规则聚合根

### 3.3 值对象

- **ID**: 唯一标识符
- **UserID**: 用户标识符
- **Points**: 积分值
- **PointsType**: 积分类型(增加/减少)
- **Source**: 积分来源
- **Description**: 描述
- **RelatedType**: 关联类型
- **TenantID**: 租户ID

### 3.4 领域事件

- **UserPointsCreatedEvent**: 积分记录创建事件
- **UserPointsRevokedEvent**: 积分记录撤销事件
- **PointsRulesCreatedEvent**: 积分规则创建事件
- **PointsRulesUpdatedEvent**: 积分规则更新事件

## 4. 领域规则

1. 积分值必须为正整数
2. 减少积分时，用户可用积分必须大于等于要减少的积分值
3. 积分类型必须是增加(1)或减少(2)
4. 积分来源必须是预定义的有效来源
5. 积分规则可配置不同行为的奖励积分和限制
6. 每日获取积分有上限
7. 只有管理员创建的积分记录可以被撤销
8. 积分记录一旦创建不可修改，只能被撤销

## 5. 应用服务

**UserPointsApplicationService** 负责协调领域对象和基础设施，提供以下功能：

1. 创建积分记录
2. 获取积分记录详情
3. 查询用户积分记录列表
4. 撤销积分记录
5. 获取积分统计数据
6. 获取和更新积分规则

## 6. 基础设施

1. **仓储实现**: 使用SQL数据库存储积分记录和规则
2. **事件总线**: 发布和订阅领域事件
3. **工作单元**: 管理事务，确保操作的原子性

## 7. 接口层

提供HTTP API，包括：

1. 获取用户积分记录
2. 创建积分记录(管理员)
3. 撤销积分记录(管理员)
4. 获取积分统计(管理员)
5. 获取和更新积分规则

## 8. 设计决策

1. **使用充血模型**: 将业务规则封装在领域对象中，使其具有行为而不仅是数据容器
2. **值对象不可变**: 确保值对象创建后不可修改，提高系统的稳定性
3. **领域事件通知**: 使用事件机制实现系统各部分的松耦合集成
4. **工作单元管理事务**: 确保领域操作的原子性和一致性
5. **仓储依赖抽象**: 通过接口定义仓储，实现基础设施与领域的分离
