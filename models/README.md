# 模型层架构设计

## 概述

本目录包含了整个微服务架构的模型定义，采用混合模型管理策略，既保持了微服务的独立性，又减少了不必要的模型重复。

## 目录结构

```
models/
├── common/       # 通用基础模型和接口
├── admin/        # 管理服务模型
├── user/         # 用户服务模型
├── content/      # 内容服务模型
├── trade/        # 交易服务模型
├── site/         # 站点服务模型
├── page/         # 页面服务模型
├── file/         # 文件服务模型
├── interaction/  # 交互服务模型
├── community/    # 社区服务模型
├── component/    # 组件服务模型
├── notification/ # 通知服务模型
├── statistics/   # 统计服务模型
└── recommendation/ # 推荐服务模型
```

## 设计原则

1. **领域分离**：按照业务领域对模型进行分类，确保清晰的边界
2. **统一基础**：所有模型继承自公共基础模型，保持一致性
3. **松耦合**：避免模型间的循环依赖
4. **完整定义**：每个模型包含完整的字段定义，包括数据库标签和JSON标签
5. **多租户支持**：所有业务模型都支持多租户
6. **SOLID原则**：遵循单一职责、开放封闭等原则
7. **DRY原则**：避免重复定义，通过组合复用

## 模型分类

### 公共基础模型 (common)

包含所有模型共享的基础结构和接口，如：
- `BaseModel`：基础模型接口
- `BaseIDModel`：包含ID字段的基础模型
- `BaseTimeModel`：包含时间戳的基础模型
- `Response`：通用响应结构

### 业务领域模型

每个业务领域目录下包含该领域的核心模型定义：

1. **管理模型 (admin)**
   - 用户权限、角色管理
   - 系统配置、菜单
   - 租户管理

2. **用户模型 (user)**
   - 用户基本信息
   - 用户认证
   - 用户偏好

3. **内容模型 (content)**
   - 内容实体
   - 分类标签
   - 评论回复

4. **交易模型 (trade)**
   - 产品
   - 订单
   - 支付

5. **站点和页面模型 (site, page)**
   - 站点配置
   - 页面布局
   - 主题设置

6. **文件模型 (file)**
   - 文件管理
   - 分类存储
   - 访问记录

7. **交互模型 (interaction)**
   - 点赞
   - 收藏
   - 关注
   - 评论

8. **社区模型 (community)**
   - 社区
   - 成员
   - 话题
   - 帖子

9. **组件模型 (component)**
   - 组件模板
   - 组件实例
   - 组件资源

10. **通知模型 (notification)**
    - 通知模板
    - 通知渠道
    - 通知记录

11. **统计模型 (statistics)**
    - 访问统计
    - 用户行为
    - 业务指标

12. **推荐模型 (recommendation)**
    - 推荐策略
    - 推荐场景
    - 用户兴趣

## 使用说明

### 引用模型

在微服务中引用模型时，应当直接引用对应的模型包，例如：

```go
import (
    "wz-backend-go/models/user"
    "wz-backend-go/models/common"
)

func CreateUser(u user.User) common.Response {
    // ...
}
```

### 扩展模型

当需要在特定微服务中扩展模型时，应在微服务的内部模型中通过组合方式引用公共模型：

```go
// 在user-service/internal/model/extended_user.go中
package model

import (
    "wz-backend-go/models/user"
)

type ExtendedUser struct {
    user.User  // 通过组合方式引入公共模型
    
    // 扩展字段
    ServiceSpecificField string
}
```

### 多租户支持

所有业务模型都包含`TenantID`字段，确保多租户隔离。在查询时应当始终加入租户过滤：

```go
db.Where("tenant_id = ?", tenantID).Find(&users)
```

## 模型演进策略

1. **兼容性原则**：模型变更必须保持向后兼容
2. **扩展而非修改**：优先通过添加字段而非修改现有字段
3. **版本管理**：重大变更时考虑引入版本号
4. **迁移脚本**：提供数据库迁移脚本

## 注意事项

1. 不要在不同领域的模型之间创建循环依赖
2. 公共字段应定义在common包中
3. 模型应只包含数据结构定义，不应包含业务逻辑
4. 所有模型必须实现JSON序列化接口
